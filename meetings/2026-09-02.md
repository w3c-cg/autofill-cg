Notes
Yoav: We have some results from the AutofillEvent experiment from Shopify, I also replied to the AutofillEvent TAG review today (https://github.com/w3ctag/design-reviews/issues/1197#issuecomment-5510929402)
(Yoav presents Autofill Event - Shopify experiment results)
Recap:
Autofill is awesome! ~30% of guest checkouts use Autofill for shopify, and they increase checkout conversion by XY%
AutofillEvent allows browser to notify website about an autofill happening, and allows developers to ask browser to re-fill after a mutation in response to the fill that happened.
Experiment:
50/50 A/B trial, of only users using autofill providers that fire the event
So entirely excluded users who couldn't have this work.
Control uses our regular 'honeypot' solution (capture all values up front, then transpose them into the modified form post-fill)
Metrics:
"Edits after autofill" boolean metric
Guardrail metrics to ensure no regression
Ran for ~1 week during August
Outcome:
Edits after autofill dropped 2-8% in many geos outside US !!
Order cancellation reduced up to 2% in some geos
Guardrail metrics remained neutral, including conversion rate.
These are very encouraging results, and we'd like to pursue the API and have it ship
Next steps:
Aiming to ship in Chromium
Needs spec cleanup + test infrastructure
Would love to see more ecosystem support (e.g., from other autofill providers, such as those in this room… 😀)
